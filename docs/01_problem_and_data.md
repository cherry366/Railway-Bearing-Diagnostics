# 01 问题与数据

## 1. 任务是什么

实际运营的高铁轴承几乎拿不到带标签的故障数据（故障一经发现就会被立刻处理），而台架
试验可以人为制造故障、批量采集。于是问题变成：

> 在**有标签但工况不同**的台架数据（源域）上训练诊断模型，再把这个模型迁移到
> **无标签、跨设备、跨工况**的实际列车数据（目标域），并对迁移结果给出可解释的证据。

四个子任务：

| 子任务 | 目标 | 对应代码 |
|---|---|---|
| 1 特征提取 | 筛选源域数据，按轴承故障机理提取时域/频域/时频域特征 | `code/data_pipeline/` |
| 2 源域诊断 | 划分训练/测试集，建模并评价 | `code/source_domain/train_classifiers.py` |
| 3 迁移诊断 | 设计迁移方法，给目标域 16 个文件打标签并可视化 | `code/transfer/` |
| 4 可解释性 | 分析事前 / 迁移过程 / 事后可解释性 | `code/explainability/` |

## 2. 源域数据

- 规模：161 个文件，由驱动端（DE，SKF6205）与风扇端（FE，SKF6203）加速度传感器采集。
- 采样率：DE 12 kHz / 48 kHz，FE 12 kHz。
- 标签：外圈 OR、内圈 IR、滚动体 B、正常 N，单一故障、无复合故障。
- 故障尺寸：OR 三档（0.007 / 0.014 / 0.021 in），IR、B 四档（含 0.028 in）。
- 载荷：0 / 1 / 2 / 3 马力，转速记录在 RPM 变量中。

轴承几何参数（用于计算故障特征频率）：

| 轴承 | 滚动体数 n | 滚动体直径 d | 节径 D |
|---|---|---|---|
| SKF6205（DE） | 9 | 0.3126 in | 1.537 in |
| SKF6203（FE） | 9 | 0.2656 in | 1.122 in |

**为什么不用基座端（BA）数据**：BA 信号经过电机整体结构、地基等多层传递与滤波，故障冲击
衰减严重、信噪比低，而且不同底座结构差异极大，用它建模容易产生负迁移。DE / FE 直接连接
转轴，故障共性更强，才是可迁移的部分。

## 3. 目标域数据

| 项 | 值 |
|---|---|
| 文件数 | 16 个（A~P） |
| 时长 / 采样率 | 8 s / 32 kHz |
| 工况 | 车速约 90 km/h，轴承转速约 600 rpm |
| 标签 | 未知 |

16 个文件只有 16 条样本，任何模型都无法直接训练——这也是必须先做滑窗扩样（见
[02_feature_engineering.md](02_feature_engineering.md)）的原因。

## 4. 数据清洗流程

`code/data_pipeline/build_label_table.py` + `denoise_detrend_normalize.py`

### 4.1 缺失通道填充

筛选中发现 8 个样本缺少 FE 通道（12 kHz，DE 端 B/IR 的 0.028 in 故障，载荷 0~3）。
若用同工况样本做简单均值填充，会破坏 DE/FE/BA 三端的时序相关性，因此采用**相似样本替换**：

1. 汇总同工况、同马力、同故障类型且 FE 完整的样本；
2. 计算完整样本 DE 信号与缺失样本 DE 信号的欧氏距离；
3. 取距离最小者的 FE 通道作为填充值。

### 4.2 异常值处理

用箱线图（IQR 准则）逐通道检测异常点，用该点前后相邻样本的均值替换。示例见
`results/figures/boxplots/`。

### 4.3 去趋势

线性去趋势：对序列拟合一次趋势项并从原信号中减去，消掉传感器温漂、工况缓慢变化带来的
线性漂移。

### 4.4 去噪

中心滑动平均滤波，窗口固定为 5 个数据点（窗口强制为奇数）：

```
y_i = (1/w) * Σ_{j=-k}^{k} x_{i+j},   w = 2k + 1 = 5
```

去噪前后对比见 `results/figures/denoised/`、`results/figures/detrended/`。处理后高频随机噪声
被抑制、慢变趋势被移除，而代表故障的周期性冲击成分被保留。

### 4.5 标准化

对每个特征做 Z-score，消除量纲与采集条件差异：

```
x_std = (x - μ) / σ
```
